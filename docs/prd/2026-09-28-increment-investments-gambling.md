## 1. 增量目标与边界

### 1.1 目标（4 个正交目标）

1. **补全可投资资产谱系**：低风险（贵金属实物/积存金）→ 中风险（期货/期权/结构化）→ 高风险（数字资产），同一账户内体验风险—收益连续谱。
2. **把赌博作为高危行为放进沙盒**：≥12 种玩法 + 钩子曲线 + 与信用/催收打通，让玩家"安全地体验一次陷阱"，并强制并列展示成瘾危害与中国内地禁赌法律。
3. **让市场"活"起来**：价格由**订单流**驱动（谁在买、买多少、吃穿几档），50x 杠杆玩家真能"拉股票"，同时付出真实反噬代价（跟风/问询/龙虎榜/限制交易）。
4. **面向中文之外的用户**：全套 UI/台词/合规文案支持中·日·英·韩，切换即时生效、可持久化、零构建。

### 1.2 边界（**明确不做**）

| 不做 | 原因 |
|---|---|
| 真实货币/真实赌博/真实链上交易 | 合规红线 + 零后端约束 |
| 后端账户、云存档、联网对战、真人对手 | 零后端约束 |
| 引入构建工具 / 打包依赖 / 需 npm 安装的运行时库 | 零构建约束 |
| 期货实物交割、期权真实做市深度撮合 | 复杂度超范围，用「现金结算 / 模型报价」近似 |
| 100% 分子级微观仿真（真实交易所级撮合/千级参与者） | 浏览器性能与零构建约束下不可行，采用 §6.12 的降级粒度 |
| 为博彩做排行榜登顶激励 / 美化赌博文案 | 价值导向红线 |
| 重写已上线功能、变动既有存档结构与既有验证用例 | 回归必须保持通过 |

## 3. 需求池（P0 / P1 / P2 · 合并版）

> **P0 = 必须做**（缺则对应模块不算交付）；**P1 = 应做**；**P2 = 可做**。
> **P0 最终条目数 = 42**（编号 P0-A1…P0-K1，见下）。

### 3.1 P0（必须做，共 42 条）

**A. 通用技术底线（5 条）**

| ID | 需求 | 理由 |
|---|---|---|
| P0-A1 | 一切随机性（赌场/代理/合成行情）走 `hash01(seed+…)` 确定性伪随机，**禁止 `Math.random()`** | 存档可复现硬约束；缺则无法回放 |
| P0-A2 | 真实数据优先；合成数据 UI 标注「模拟历史」 | 不冒充真实行情 |
| P0-A3 | 两版同步实现（引擎逻辑一致，文案/皮肤各自适配） | 两版都要做 |
| P0-A4 | 现有全部功能与 `verify*.js`/`verify-teiai.js` 保持通过 | 回归硬约束 |
| P0-A5 | 纯静态 / 零构建 / 零后端 | 架构硬约束 |

**B. 多语言 i18n（6 条）**

| ID | 需求 |
|---|---|

### 5.7 钩子曲线（Hook Curve）—— 核心机制

**定义**：`E_eff` = 有效庄家优势（相对投注额；**负数 = 玩家有利**，正数 = 庄家有利）。

| 参数 | 取值 | 说明 |
|---|---|---|
| `hookLeft` | 首次入场 8~15 局，由 `hash01(seed+'#casino'+venue+'#hook')` 确定性取值 | 两场独立维护 |
| 甜头期（`round < hookLeft`） | `E_eff = −(2%~6%)`，由 `hash01(...+'#'+round)` 在区间内插值 | 玩家正期望，"一开始真能赢" |
| 惩罚期（`round ≥ hookLeft`） | `E_eff = +(8%~15%)` | 庄家优势回归并超额 |
| 追损加速 | 连续亏损时 `E_eff += min(5%, 0.8% × 连亏次数)` | 损失厌恶陷阱 |
| 残酷度档（`casinoEdge`） | 低：甜头 −6%~−3% / 惩罚 +8%~+11%；标准：−4%~−2% / +10%~+13%；残酷：−3%~−2% / +12%~+15% | 默认标准 |

**期望值曲线（前 20 局，示例：hookLeft=10、甜头 −4%、惩罚 +11%、追损 0.8%/次）**

| 局 | 阶段 | 单局期望 E_eff（相对投注额 B） | 累计期望 |
|---|---|---|---|
| 1–10 | 甜头期 | **−4%**（玩家 +4%×B） | +40%×B |
| 11 | 惩罚期 | +11%（玩家 −11%×B） | +29%×B |
| 12 | 惩罚期 | +11% | +18%×B |
| 13 | 惩罚·连亏1 | +11.8% | +6.2%×B |
| 14 | 惩罚·连亏2 | +12.6% | −6.4%×B |
| 15 | 惩罚·连亏3 | +13.4% | −19.8%×B |
| 16 | 惩罚（重置连亏） | +11% | −30.8%×B |
| 17–20 | 惩罚期 | 约 +11%~+16% | 持续走负 |

**为何既满足用户、又强化「庄家永远赢」警示**：钩子曲线精确复刻真实赌场的"杀猪盘"体验——先给甜头建立"我能赢"的错觉与**加注习惯**（甜头期玩家倾向加大投注，使实际损失更大），再用正期望收割。数学上长期期望必为负（惩罚期优势远大于甜头期），与项目一贯的「庄家最终一定赢」警示立场一致。

### 5.9 市场微观结构数值（增量四核心）

**Kyle's λ（价格冲击）**

| 档位（`microLevel`） | λ_sqrt | 说明 |
|---|---|---|
| 关闭 | — | 退回滑点公式，`px=raw.c×k`，`k===1` |
| 简化 | 0.006 | 冲击温和 |
| 标准（默认） | 0.010 | 见下弹性表 |
| 硬核 | 0.015 | 冲击显著、反噬更频繁 |

**可拉抬弹性曲线**：`ΔP/P = λ_sqrt × sqrt(X / ADV)`（X=玩家净买入金额，ADV=该标的 20 日均成交额）。
标准档 λ_sqrt=0.010 时：

| X/ADV | 5% | 10% | 25% | 50% | 100% | 200% | 300% | 500% |
|---|---|---|---|---|---|---|---|---|
| 理论拉抬 | 0.22% | 0.32% | 0.50% | 0.71% | 1.00% | 1.41% | 1.73% | 2.24% |

- **小盘易拉、大盘难拉**：同一 X 元，小盘股 ADV 小 → X/ADV 大 → 拉抬显著；且叠加**流通盘约束**（X 接近流通市值一定比例 → 涨停/异常波动/限制交易）。
- **涨停封顶**：受涨跌停（±10%）与反噬阈值约束，不会无限拉。

**五类参与者代理参数（日维度）**

| 代理 | 单笔金额 | 日均参与笔数 | 参与标的 | 行为特征 | 换手 |
|---|---|---|---|---|---|
| 散户 | 0.5~5 万 | 高（数百笔） | 全部 | 追涨杀跌、羊群、处置效应（浮盈卖/浮亏扛） | 高 |
| 游资 | 50~500 万 | 低（数笔） | 中小盘/题材 | 脉冲拉抬、隔日了结 | 中高 |
| 机构 | 200 万~2000 万 | 低（1~3 笔） | 权重蓝筹 | 分批建仓、VWAP | 低 |
| 做市商 | 双边 | 持续 | 全部 | 双边报价、库存偏好、价差随波动放大 | 库存管理 |
| 量化 | 2~50 万 | 极高 | 流动好的标的 | 动量+反转因子、均值回归 | 高频 |

**价差模型**：`spread = max(tick, k_spread × 波动率 / sqrt(深度))`；深度随 ADV 与参与代理活跃度变化。
**跟风强度**：日内涨幅 >3% 或 累计净流入 >0.5×ADV → 触发散户跟风，跟风买入量 = 玩家净买入 × ρ，ρ∈[0.3, 0.8]（种子确定性，人气/题材上升时增大）。
**反噬触发阈值**

| 事件 | 触发阈值 |
|---|---|
| 异常波动问询 | 日内涨幅 >7% 或 3 日累计 >15% |
| 龙虎榜 | 单日净买入 >20%×ADV |
| 限制交易 | 3 日累计 >20% 或 单日涨停且封单量 >流通盘 1% |
| 获利盘涌出 | 跟风盘浮盈 >5% 后触发抛压（处置效应）→ 反噬回落 |
| 砸盘反噬 | 日内跌幅 >7% 同理触发（问询/资金出逃） |

### 8.2 微观结构**可验收口径**（P0-C10，最重要）

> **定义基线**：同一存档、同一交易日 t、同一随机种子，跑「玩家不参与」的订单流模拟，得 t+1 收盘价 `P_base`；玩家在 t 日净买入 X 元后得 `P_player`。

| 编号 | 断言 | 通过标准 |
|---|---|---|
| A1 | 价格由订单流驱动 | `dev = |P_player − P_base| / P_base` **单调递增**于 `X/ADV` |
| A2 | 弹性定量 | 标准档：`X/ADV=10% → dev ≥ 0.3%`；`50% → ≥ 0.7%`；`100% → ≥ 1.0%`；`300% → ≥ 1.7%` |
| A3 | 小盘易拉 | 同一 X 元，小盘股（ADV 小）`dev` **显著大于**大盘股（ADV 大） |
| A4 | 关闭 micro 归零 | `opt.micro=false` 时 `dev == 0`（或 `< 1e-9`），且价格严格 `px=raw.c×k` 且 `k===1`（与现有 verify 降级断言对齐） |
| A5 | 分时来自逐笔 | 分时线各分钟点 = 该分钟内逐笔成交聚合（可由 tick 序列复算校验） |
| A6 | 确定性 | 同种子同订单 → 逐笔序列与 `P_player` 完全一致（重放一致） |
| A7 | 反噬触发 | 净买入 >20%×ADV → 出现龙虎榜事件；日内 >7% → 出现异常波动问询 |
| A8 | 性能 | 标准档 `stepDay(1)` < 50ms；关闭 micro 无额外开销 |

## 附录 C：实现要点（供架构师参考，非约束）

1. **最大化复用**：期货/期权保证金并入 `usedMargin()`；私募/结构化复用理财中心账务不变式「现金买入→realized-= / cashAssets+= → 到期结算」。
2. **日结插入点**：`stepDay()` 逐日循环内新增 `settleFutures()`、`settleOptions()`、`settleAlts()`、`runPmDca()`、`settleMicro()`（订单流按日推进）；赌场即时交易走 `hash01`；赌债利息走 `accrueIllegal()`（复用）。
3. **确定性**：全部新随机性经 `hash01(G.bSeed + …)`；`reset()` 已有 `bSeed`。
4. **micro 优先于影子价**：`opt.micro` 开启时价格由订单流出清，影子价 `k` 仅作为外力成分；**关闭时严格退回 `px=raw.c×k` 且 `k===1`**。
5. **数据解耦**：合约乘数/保证金率/权利金参数、钩子曲线参数、λ/代理参数等"规则常量"放 `game.js`；`snapshot.js` 只承载价格序列 + meta + 微观派生参数（adv/float/depth）。
6. **两版同步**：`market.js`/`i18n.js`/词典/`snapshot.js`/`fetch_data.py` 逐字节一致；`game.js`/`ui.js`/`chart.js`/`index.html`/`style.css` 在两版同步实现，仅文案/皮肤不同。
7. **i18n 优先**：所有新增 UI 文本一律走 `t(key)`，禁止硬编码；新增 key 必须同时补全 4 语言（缺漏在构建期/校验脚本报错）。
